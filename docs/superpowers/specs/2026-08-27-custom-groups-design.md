# 自定义分组设计(每组数量可不同)

日期:2026-08-27
状态:已获用户批准

## 背景与目标

当前「分组完成(高级)」功能只提供**整除**分组方案(`FTLogic.groupOptions`),如
100 个只能 `2组×50`、`4组×25`,无法做 `34+33+33` 这类每组数量不同的拆分。

目标:支持自定义分组——输入组数自动生成近似均匀拆分,再逐组微调数量,
一键应用于当天全部 5 个项目。

## 需求决策(已确认)

1. **输入方式**:输入组数 → 自动拆分 → 逐组微调(而非自由手打数量序列)。
2. **总和约束**:自动补差到最后一组——微调前 n-1 组后,最后一组 = 目标 − 前面组之和,
   只读置灰,总和永远等于目标。
3. **数据模型**:统一迁移为 `groupReps` 数组(方案 A),读取时兼容旧 `sets/reps` 格式。

## 交互设计

### 入口与面板

- 「分组完成(高级)」折叠区内,chips 行尾新增 `✏️ 自定义` 按钮。
- 点击在 chips 下方展开面板;再点收起。不新开弹窗。
- 面板结构:

```
组数 [ 3 ]  ← change 后自动重新生成
第1组 [34]  第2组 [33]  第3组 [+33]   ← 最后一组只读,自动补差
合计 100 / 100 ✓            [应用分组]
```

### 规则

- **自动拆分**:`base = ⌊T/n⌋`,余数 r 分给前 r 组(前大后小,100÷3 → 34+33+33)。
- **组数范围**:2 ~ 目标值 T(1 组方案已有现成 chip)。
- **微调**:前 n-1 组可编辑,`inputmode="numeric"` 数字键盘;输入时**实时重算最后一组**,
  仅做面板局部 DOM 更新(不触发全量重渲染,避免丢焦点)。
- **补差校验**:每个可编辑组须为 ≥1 的整数(0、小数、空均视为无效);
  前面组之和过大导致最后一组 ≤ 0 → 红字「前面组数量过大」+ 应用禁用。
  错误只在面板内提示,不弹 alert。
- **应用**:校验通过 → 一键作用于 5 项(重置分组进度,与现状一致)→ 面板收起。
- **草稿**:面板输入值存 `app.customDraft`;中途其他打卡操作触发重渲染后,
  面板从草稿恢复,不丢输入。
- **当前方案摘要**:已应用分组时标题行显示 `当前 4 组 · 34+33+33`;
  chips 高亮仅在当前分组恰好均匀时生效。
- **逐组按钮显示数量**:批量区与单项卡的组按钮改显示每组个数(如 `34 ✓`),
  组号移到 `title` / `aria-label`。

## 代码改动

| 文件 | 改动 |
|---|---|
| `logic.js` | 新增 `splitEvenly(total, sets)`:返回前大后小的数量数组;非法入参返回 `null`。`groupOptions` 保留 |
| `store.js` | `_exercise()` 规范化:旧 `{sets, reps}` → `groupReps = Array(sets).fill(reps)`;记录形态变为 `{completed, groupReps, setDone}`;`applyGroups/applyGroupsAll` 接收数组;`_setSetDone` 的 `completed = Σ setDone[i] ? groupReps[i] : 0`;`clearGroups/resetExercise` 清空 `groupReps` |
| `ui.js` | `renderBatchSection` 渲染自定义按钮 + 面板(参数:展开态、目标、草稿);chips 高亮改为「当前 `groupReps` 恰好均匀」才生效;当前方案摘要;逐组按钮显示数量;`renderExerciseCard` mini 组按钮同步改 |
| `app.js` | 新增 `customGroupsOpen` / `customDraft` UI 态;委托处理 `toggle-custom-groups`、组数 `change`、`apply-groups-custom`;输入 `input` 事件仅局部更新面板 |
| `styles.css` | 面板、只读补差框、红字错误态样式 |

## 兼容性

- localStorage 旧数据**不迁移**:仅在读取时经 `_exercise()` 规范化;
  某天记录被操作后写回自然变为新格式,未动过的旧记录永远可读。
- 本项目为本地 PWA,Service Worker 缓存版本只前进部署,不考虑前端回滚读新格式的场景。

## 测试计划(`node --test`)

- `splitEvenly`:整除;不整除前大后小;非法组数(<2、>total、非数字)返回 `null`。
- `applyGroups(数组)`:`groupReps` 存储正确,`setDone` 长度对齐。
- 非均匀分组逐组打卡:`completed` 按 34+33 累加。
- 旧数据兼容:构造 `{sets:4, reps:25}` 旧记录,打卡后 `completed` 仍正确。
- 清除分组 / 归零:`groupReps` 清空、`setDone` 清空。

## 不做的事(YAGNI)

- 不持久化「记住上次自定义分组」。
- 不支持 5 项各自不同的分组方案(保持与现有批量交互一致)。
- 不支持只填数量序列的自由输入模式。
